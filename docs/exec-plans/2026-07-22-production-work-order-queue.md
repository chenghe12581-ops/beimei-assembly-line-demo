# 生产执行工单排单层级改造

## 目标

- 将生产执行左栏当前任务概要升级为工单概要，支持同时展示和创建多张工单。
- 第一张工单继续承载 `0162-01-010101 × 6` 的现有执行 Demo。
- 工单概要提供排单序号、折叠 caret、工件图号、数量、理料状态下拉和总体进度；整条概要可拖动排单，但不显示独立抓手。
- 未执行工单在理料状态左侧提供 hover 删除入口，并通过确认弹窗完成排单移除。
- 工单条目不使用外壳 stroke，工单 stack 的顶部与左右 padding 统一为 `8px`。
- 展开工单后直接显示现有 WP 容器与工序条目，不增加中间卡片或改变既有样式。

## 约束

- 不修改 WP 容器的结构、尺寸、背景、边框、间距和交互。
- 不修改 WP 内部工序条目的结构、尺寸、颜色、状态灯、禁用态和批量选择样式。
- 不修改生产工作台、工位 / 托盘映射、自动推进、单步调试和视觉异常 Demo。
- 保留当前工作区内已有的视觉监控、托盘管理和其它未提交改动。

## 实现步骤

1. 扩展生产任务的排单展示字段，准备一张真实 Demo 工单和六张待执行 Demo 工单。
2. 将 `ProductionTaskTreePanel2` 的任务概要改造成工单概要，增加折叠和排单序号交互。
3. 保持现有 WP 与工序 JSX 原样，仅由工单展开状态控制是否挂载。
4. 将新建入口与弹窗文案改为“新建工单”，新建结果追加到排单末尾。
5. 更新生产执行领域规则、产品规格和 Component Lab 的事实来源。
6. 运行构建并验证生产执行页与组件库的分栏 / 平铺视图。

## 验收重点

- 默认折叠全部工单，点击第一张后展开 `0162-01-010101 × 6` 的现有 WP 与工序内容。
- 数量紧跟工件图号显示，折叠 caret 位于概要左侧。
- 展开前后 WP 容器和工序条目视觉样式无变化。
- 新建工单不再受现有列表非空限制，并追加在队尾。
- 第一张工单初始化、执行、暂停、工位映射、托盘流转和视觉异常行为保持不变。

## 新建工单弹窗再拔一级

### 目标

- 弹窗最左侧固定为工单栏，用户可连续新建多张临时草稿工单，工单号由前端自动生成。
- 每张草稿工单独立保存装配体选择、工序禁用、加工数量、配盘结果和当前配置步骤。
- 工序预览下方的「下一步」只推进当前选中工单到配盘阶段；数量留在「加工设置」，局部 footer 通过「返回任务设置 / 确认工单」完成当前草稿确认，弹窗 footer 的「确认新建」一次提交左栏全部已确认草稿。

### 布局

1. 固定工单栏：宽约 `240px`，顶部使用「新建工单」文字按钮，下方纵向 stack 草稿卡片。
2. 两个阶段共享结构：工单栏右侧保留项目管理结构树；上部视窗和下部两列设置 / 预览区域保持同一尺寸与位置。
3. 配盘阶段只替换上部为托盘依据视图，并将原工序预览位置替换为托盘卡片；加工数量继续显示在「加工设置」中。
4. 整个弹窗 footer 只保留「取消」与「确认新建」；局部 footer 依次放置「返回任务设置」与「确认工单」。

### 交互与验收

- 新建草稿后自动选中；切换工单卡片时恢复该卡片独立的配置与阶段。
- 工单卡片显示「待选择任务 / 待设置数量 / 待确认 / 配置完成 / 托盘不足」。
- 只有全部草稿均已选装配体、数量有效、无托盘溢出且点击过「确认工单」时，「确认新建」才可用。
- 确认后按左栏卡片顺序追加到生产排单，并保留每张工单的软禁用工序。
- 主页执行器仍直接消费单条 `ProductionTask`，本改造不改动自动推进、单步调试、视觉异常或 AGV 状态机。
