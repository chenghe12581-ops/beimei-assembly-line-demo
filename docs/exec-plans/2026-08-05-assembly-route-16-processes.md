# 装配体 16 道工序路线同步

## Goal

- 将样式 C 工艺规划和生产执行共用的固定路线从 15 道更新为 16 道。
- 补充翻面后将 `02 + 01` 装配体送入主筋板装配工位2的上料工序。
- 统一六个现场工位名称和显式回显位置映射。
- 装配工序只保留一个焊接任务，并在任务内部维护扫描和焊接两套配置。

## Context

- 当前固定路线由 `src/app/process-planning-model.ts` 共享给工艺规划和生产执行。
- 当前路线仍使用打磨工位、正面拼装工位、背面拼装工位、筋板及贴板翻转工位等旧名称。
- 当前样式 C 完整填充实际生成 25 项任务；新增装配体上料的抓取和放置后应为 27 项。
- 生产工作台已经存在六个现场工位，但部分工序映射和主筋板打磨工位名称仍与新路线不一致。

## Scope

- 更新固定工序顺序、对象、工位名称、回显位置和允许任务类型。
- 保留已有工序 ID，仅新增第 08 道工序 ID，降低已有任务配置迁移风险。
- 更新样式 C 完整 Demo 填充顺序和任务数量。
- 更新生产执行 16 道任务树、工位高亮、工位工步模板和进度语义。
- 更新 Component Lab、产品规格、领域规则和验收文案。

## Non-goals

- 不修改样式 A / B / D 的 Legacy 24-task 留档顺序。
- 不把生产执行右侧的设备级工步写入工艺规划任务。
- 不合并焊接任务内部的扫描参数、扫描点位、焊接参数和焊接点位。
- 不引入新的状态管理方案或后端 API。

## Steps

1. 更新领域文档中的 16 道固定路线和 27 项任务口径。
2. 扩展共享固定工序模型，增加稳定回显位置 ID 和焊接正反面字段。
3. 更新样式 C 完整任务生成，补充第 08 道抓取与放置任务。
4. 更新生产执行的工位映射、工步模板和六工位名称。
5. 同步 Component Lab 的工序总览、装配任务和生产工位示例。
6. 构建并回归工艺规划、生产执行、虚拟仿真和组件库。

## Verification

- `npm run build`
- 样式 C 固定展示 16 道工序，顺序、对象和工位与领域表一致。
- 完整 Demo 填充生成 27 项任务，第 07 道为翻面，第 08 道为 `02 + 01` 上料。
- 三道装配工序各包含装配、翻面压紧、焊接三个任务。
- 生产执行每个完整 WP 展示 16 道工序，并按显式位置映射高亮工位或托盘。
- 第 14 道侧面打磨明确回显在主筋板装配工位2。
- 焊接仿真不再通过旧工位中文名称推断正反面。
- Component Lab 分栏和平铺视图无文本溢出。

## Risks

- 生产执行的工位映射同时服务新版聚合工序和 Legacy 演示任务，修改时需保留旧任务 ID 的兼容映射。
- 工序序号变化会影响按数组索引实现的 Demo 快捷入口，需要优先使用稳定工序 ID。
- 工位中文名称改动会破坏字符串比较逻辑，正反面和回显位置必须改为显式字段。
