## 工程边界

- `BeimeiAssemblyLinePage.tsx`：只负责统一导航、工艺任务数据适配、入口和返回回调。
- `src/app/VirtualSimulationPage.tsx`：只负责工作区组合、提示和导出编排。
- `src/features/virtual-simulation/components/`：任务栏、工具栏、视窗、播放器和程序栏。
- `src/features/virtual-simulation/hooks/`：任务选择、程序状态和播放状态。
- `src/features/virtual-simulation/services/`：加工程序生成和程序树查找；后续真实后处理器继续从这里替换。
- `src/features/virtual-simulation/types.ts`：工艺任务适配对象、程序、指令和场景类型。

## 后续阶段

1. 后处理器：按实际机器人品牌和控制器格式替换当前演示生成器。
2. 仿真时间轴：将每条指令映射为机器人关节、TCP 和外部轴运动。
3. 机构模型：接入真实正面/背面工位、支撑、压紧和机器人资源。
4. 校验反馈：增加越界、不可达、碰撞、速度和工艺指令完整性检查。
5. 持久化：若后续需要跨会话保留仿真副本，再增加独立设计和 service/API。

## 验证

1. 运行 `npm run build`。
2. 检查无任务空状态下播放器常驻且全部禁用。
3. 从工艺规划第 06 道装配工序反复发送虚拟仿真，检查每次都新建副本，并携带翻面压紧轴值与扫描/焊接点位。
4. 检查模型拖拽旋转、右键平移、滚轮缩放和重置。
5. 生成程序后检查 Robot1/2、扫描程序、焊接程序、PTP/LIN、工艺命令和目标位姿；特别检查每个子程序固定生成 6 点，`P_APPROACH_1` 为 `J1-J6 + E1 + S` 的关节点，`P_SCAN_START / P_WELD_START` 至 `P_DEPART_1` 为 `X/Y/Z/RX/RY/RZ + E1 + S` 的笛卡尔点。
6. 检查顶部多副本菜单、本地导入示意流、程序生成后可直接本地导出，以及返回工艺规划后第 06 道上下文恢复。
7. 检查加工程序1的支撑机构 J1-J8、压紧机构 J1-J6 slider、stepper 输入和间距与工艺规划一致，扫描/焊接程序参数使用相同的紧凑字段样式。
8. 拖拽程序列表与详情区之间的分隔条，确认上下幅面可调且任一区域不会被完全压缩。
9. 检查左侧焊接任务下固定 6 个焊缝段且无点数文案；焊接任务选择回显全部 24 个标记，单段选择只回显 `Sx-1/Sx-2/Wx-1/Wx-2`。
10. 打开程序生成弹窗，逐段切换执行机器人，确认生成后的 Robot1/Robot2 程序树按焊缝段分组且同段扫描/焊接不会分配到不同机器人。
11. 检查 Component Lab 分栏和平铺视图中的共享 P1-P6 点位标记预览。
12. 在数模查看输入平移和旋转值，确认装配体、焊缝和点位同步变换而工位设施不移动；切换仿真副本后确认各自的位置输入独立保留，并检查世界/父系坐标切换与浮窗折叠。
