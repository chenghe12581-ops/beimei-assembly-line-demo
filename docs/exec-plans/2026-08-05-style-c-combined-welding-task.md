# 样式 C 扫描焊接合并任务

## Goal

- 仅在样式 C 的装配工序中，将“定位焊扫描”和“定位焊”合并为一个“焊接”任务。
- 合并任务内部保留扫描与焊接两套独立、可编辑的工艺参数和路径点位。
- 扫描点位与焊接点位均使用 6 组结果点和安全点。

## Context

- 当前定位焊扫描和定位焊是两个独立任务，并共用 `FeatureProcessConfig` 结构。
- 扫描路径当前使用 6 组，定位焊路径当前使用 4 组，直接共用一份点位数据会发生覆盖。
- 样式 A / B / D 是历史方案，需要保持现有两个独立任务和现有交互不变。

## Scope

- 为样式 C 增加明确的合并焊接任务类型和扫描子配置。
- 样式 C 固定装配工序只允许新增一个焊接任务。
- 样式 C 一键填充时生成一个焊接任务，同时生成扫描和焊接两套配置。
- 工艺参数详情按“扫描参数 / 焊接参数”分区并允许编辑。
- 路径点位详情增加“扫描点位 / 焊接点位”分段选择；坐标系、折叠和安全点配置作用于当前分段。
- 同步产品规格、领域规则和 Component Lab。

## Non-goals

- 不修改样式 A / B / D 的任务类型、任务数量、生成顺序和详情布局。
- 不修改生产执行中的工位工步。
- 不引入后端 API 或新的状态管理方案。

## Steps

1. 扩展样式 C 固定工序允许的任务类型与合并任务配置。
2. 更新样式 C 新增任务和一键填充逻辑。
3. 实现合并任务的参数分区、点位分段、重置、脏状态和安全点编辑。
4. 将焊接点位扩展为 6 组，并保持扫描点位为 6 组。
5. 同步 Component Lab 和规范文档。
6. 构建并检查样式 C，同时回归样式 A / B / D。

## Verification

- `npm run build`
- 样式 C 装配工序只显示一个焊接任务入口和一个生成后的焊接任务。
- 合并任务工艺参数中的扫描参数、焊接参数均可修改并产生未保存状态。
- 路径点位可在扫描点位和焊接点位间切换，两侧均为 6 组且数据互不覆盖。
- 安全点配置编辑当前分段对应的安全点。
- 样式 A / B / D 继续显示独立的定位焊扫描和定位焊任务。
- Component Lab 分栏和平铺视图不溢出。

## Risks

- 页面现有点位、预览和脏状态大量按 `step.id` 关联，合并后必须同时识别当前子阶段。
- 样式 C 与样式 D 共用部分紧凑详情组件，所有新分支必须以合并任务类型隔离，避免影响样式 D。
- 当前工作区有其它未提交修改，实施过程中只做增量编辑并保留既有变更。
