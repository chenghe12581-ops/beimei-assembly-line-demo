# 托盘物流状态演示执行计划

## Goal

用可操作的前端 mock 演示 `00 -> 01` 上料、`01 -> 00` 空托回收和 `09 -> 10` 成品下料。生产监控托盘卡片只表达托盘、料框和 AGV 的现场状态，不再由左侧工序的工位映射直接激活。

## Scope

- 扩展托盘和 AGV demo 状态，支持图外点位 `00` 与 `10`。
- AGV 执行时将可视目的地标记为已预约；确认到达时将料框与零件载荷从来源原子迁移至目的地。
- 左侧任务首次执行时触发明确的“工位接料” mock，将 01 号托盘中的零件移入工位 WIP，留下空托。
- demo 不等待 WP 全部工序结束：空托回收完成后 mock 09 号成品托盘到位并执行 `09 -> 10` 满托任务，完成后释放 09。
- 更新生产监控托盘卡片、托盘管理实际视图和 Component Lab 示例。

## Non-goals

- 不接入 PLC、AGV、MES 或仓储系统。
- 不改变工艺规划中的工序定义和工位状态机。
- 不把 00、10 画入当前 01-09 产线底图。

## Verification

1. 执行 `00 -> 01` 后，01 显示零件01和 5 件。
2. 启动左侧任务后，01 由已占用变为空托在位，并可执行 `01 -> 00`。
3. 执行中的可视卸货点显示已预约；确认到达后来源释放、目的地保留载荷。
4. mock 自动完成 `01 -> 00` 空托回收、09 成品到位与 `09 -> 10` 下料，结束后 09 回到空闲。
5. Component Lab 的水平和 skew 托盘卡片均包含空闲、已预约、零件到达、空托回收中、成品下料中和下料完成变体。
6. 运行 `npm run build`。
