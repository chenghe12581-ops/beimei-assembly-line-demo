# 托盘计划视图与零件俯视图改造计划

## Goal

重构托盘管理的计划视图，使用户先理解 01-09 号托盘在现场的位置关系，再查看每个托盘包含的零件种类与数量。每种零件使用真实 STL 生成的俯视图图例；多料托盘暂时使用单列摆放变体，不表达未经现场尺寸验证的左右分栏或精确物理坐标。

## Scope

- `src/app/components/production/TrayManagement.tsx`
  - 计划 / 实际视图共用真实托盘区位底图。
  - 下方托盘明细固定按 `09 / 08 / 07 / 06 / 05 / 04 / 03 / 02 / 01` 排列。
  - 托盘内部保持连续承载面，多种零件按单列无分隔线摆放。
  - 计划视图展示零件俯视图、零件号和数量；实际视图仅在 AGV 任务包含明确零件时展示对应俯视图。
  - 单料和多料使用同一种紧凑条目，俯视图缩小为约 `36 × 24px`，放大零件名称，保证单卡能容纳四种零件。
  - 上层区位图不显示物流方向文字，区域标签下移并居中在所属托盘矩形总横宽上方，09 号占用框向左校准到 SVG 托盘位置。
  - 区域标签、上层托盘编号和下层卡片编号使用同一区域色，已配盘 / 已占用由状态文字独立表达。
  - 计划矩形、实际矩形、任务预览矩形和下层卡片共用区域色表面样式，视图差异收敛到状态文字。
- `public/part-topviews/`
  - 从 `public/models/0162-01-010101-01.stl` 至 `-04.stl` 生成透明 PNG 俯视图。
- `public/tray-visualization/tray-zone-legend.svg`
  - 从原始区位 SVG 派生，移除底图自带的 01-09 路径文字和装配区域 stroke，并提高底图可见度。
- `src/app/ComponentLabPage.tsx`
  - 同步空托盘、单料、多料单列和实际占用状态。
- `docs/frontend/tray-management.md`
  - 记录上下两层观看顺序和俯视图样式。
- `docs/domain/production-execution.md`
  - 记录当前单列摆放仅为 demo 可视化模板，不代表现场尺寸校核结果。

## Constraints

- 不修改 AGV 点位互斥、任务执行或配盘分配规则。
- 不把零件俯视图的视觉位置解释为真实托盘放置坐标。
- 不在托盘内部绘制料框、网格或分割线。
- 托盘图例工作区使用白底，区域名称由 HTML 层回显，不复用 SVG 内的描边。
- 不为每个俯视图创建独立 Three.js 画布。
- 不修改 `dist/assets/*.js`，由 `npm run build` 重新生成。

## Verification

1. 运行俯视图生成脚本并检查 4 个透明 PNG。
2. 运行 `npm run build`。
3. 在生产执行页打开托盘管理：检查计划视图区位图、02 号多料单列、单料托盘和空托盘。
4. 切换实际视图：确认只回显执行中 AGV 点位，且没有运行中任务时保持灰态。
5. 检查 Component Lab 分栏与平铺视图。
