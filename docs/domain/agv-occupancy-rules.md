# AGV Occupancy Rules

## Scope

本规则约束托盘管理页面中的 AGV 任务执行、理料区视图点位回显和执行互斥判断。整体区位图只表达现场状态；下方托盘卡片表达配盘计划，不参与 AGV 点位锁定。生产监控与理料区整体区位图共享同一份现场托盘状态。

## Point Occupancy

- 可视卸货点在 AGV 任务为 `执行中` 时进入 `已预约`，不提前写入零件和数量。
- 满托或上料任务的可视取货点在执行中保留现有 `已占用` 与载荷信息，并回显任务正在取货；空托任务的取货点显示 `空托取货中`。
- 确认到达时，系统必须以单次状态迁移释放来源并将料框、零件对象和数量写入可视卸货点。空托只迁移料框，不写入零件载荷。
- 任务完成后不得无条件释放卸货点；只有来源释放。图外 `00` 与 `10` 不进入 01-09 托盘图，但在 AGV 路线中可用。
- 点位状态为：`空闲`、`已预约`、`空托在位`、`已占用`。`已占用`必须展示零件或成品名称和数量。
- 上料任务确认到达后，整体区位图在对应实际占用点位回显零件名称和“已占用”。用户可点击该实际占用点位，将其释放为“空托在位”；该操作不改写已完成的 AGV 任务记录，也不影响下方计划摆盘卡片。计划配盘中的满盘提示属于容量预览，不作为现场占用判定。

## Mutual Exclusion

- 点击 `执行` 前，系统必须收集所有 `执行中` AGV 任务的可视取货点和卸货点。
- 已归档任务不参与取货点、卸货点占用收集，也不参与理料区计划任务匹配。
- 待执行任务的可视取货点或卸货点只要与任一执行中任务的锁定点位重合，就不能执行。
- 冲突时任务保持原状态，不进入 `执行中`，并提示用户该点位已被执行中 AGV 任务占用。
- 冲突反馈应落到当前任务行的具体点位字段：仅将重复的 `取货点` 或 `卸货点` 下拉框标红；用户点击其他任务行或修改任一点位后取消标红。
- 不冲突时，任务进入 `执行中`，托盘整体视图立即回显可视卸货点为已预约。

## Demo Timing

- 当前 demo 中，点击 `执行` 后任务进入 `执行中`。
- 用户点击 `确认到达` 后任务切换为 `已完成`，以便检查取货、预约和到达三个状态。
- 理料区计划托盘卡片首次点击 `执行` 时，系统按卡片物料创建或复用一条 `00 -> 目标托盘位` 的上料任务并直接进入 `执行中`；该任务后续仍遵守相同的点位互斥和确认到达规则。

## UI Rules

- 执行中任务行使用橙色左侧高亮和状态 badge 脉冲反馈。
- 执行按钮点击后进入置灰禁用态；执行中行显示 `确认到达`。
- 已完成任务行回到默认行底色，仅保留 `已完成` badge。
- 状态列只读回显，不提供下拉修改。
- 理料区计划托盘卡片序号行同时显示 `执行` 和 `确认到达`：待执行时仅执行可用，执行中时仅确认到达可用，已完成时两者均禁用；其它执行中任务锁定 `00` 或目标托盘位时，执行按钮提前禁用。
