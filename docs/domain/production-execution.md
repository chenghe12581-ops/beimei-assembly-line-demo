# Production Execution Domain

## Concepts

- 工单：生产执行左栏的排单单元，包含自动生成的工单号、排单顺序、一项工件任务、加工数量、工单状态和总体进度。当前原型一张工单只包含一项工件任务。
- 生产任务：工单内从工艺规划工件创建的现场执行任务，包含工件、数量、已选工序和工件实例；现有执行器继续直接消费该任务，不因新增工单层级改变。
- 工件实例：生产任务下的单件加工对象，用于跟踪当前工序、进度和视觉信息。内部 `serial` 继续使用 `WP-01` 格式，所有用户可见位置统一格式化为 `工件-01`。
- 任务状态：任务级别的执行状态，包括待初始化、就绪、加工中、暂停、已停止、已完成、异常。
- 工序任务：生产执行中可取消勾选的工艺流程节点，用于单步调试或完整加工。
- 单步调试工位快照：根据显式工位映射从当前生产任务推导的只读现场上下文，包含当前工序任务、加工零件、任务数量和工件实例。
- 聚合工步：执行面板用于拆解当前工位聚合任务的可执行单元；装配工步中的贴板标签使用完整 `partObject` 零件名称，焊缝标签使用当前工件组合关系形成的序号。
- 复合工位：跨物理工位的复合执行单元。复合工位1 = 主筋板装配工位1 + 贴板打磨工位1，复合工位2 = 主筋板装配工位2 + 贴板打磨工位2；四个物理工位在工作台保留卡片和状态，但工位详情按复合工位聚合展示，标题为加号相连的复合名称。复合工步列表是若干工序段落的有序拼接（上料段 → 打磨段 → 装配段，复合工位2 追加 04 零件的打磨段 + 装配段和下料尾段），当前工步高亮由「活动工序 → 段落起点 + 段内 `currentStepIndex`」推导；任务推进引擎的 per-process `currentStepIndex` 语义不变。v1 归档流程的设备级子工序通过显式别名表归入对应段落。
- 生产模型视图：生产执行顶部悬浮 tab 的一级视图，用于在执行场景中查看当前任务工件结构和工序关联零件。
- 托盘配盘：根据工件和数量生成的人工理料清单，指导上料托盘、中托盘和物料数量。
- AGV 调度任务：围绕上料、空托、满托创建的物流任务，可自动生成或手动执行。
- 设备状态：PLC、机器人、相机等设备连接状态，用红 / 灰 / 绿表达异常 / 未连接 / 连接。

## Task State Rules

- 新建工单先保存在弹窗的待下发缓存区，不创建生产任务；只有被勾选并点击「下发生产」后，才追加到生产任务列表并进入待初始化状态。
- 生产执行允许同时存在多张工单；排单顺序由左栏位置表达，工单概要不显示排单序号。待执行工单可拖动整条概要调整顺序，运行中、暂停和异常工单不可调整顺序。概要不显示独立拖动抓手。
- 已下发但未执行的工单允许从生产任务列表删除；删除入口位于状态左侧，仅在工单概要 hover / focus 时显示。删除必须二次确认，只移出当前生产任务列表，不删除工艺规划数据。
- 工单概要折叠只影响左栏内容可见性，不修改选中任务、活动任务或执行状态。
- 初始化只能作用于未执行、暂停或已停止任务；初始化后任务进入就绪。
- 执行只能作用于可运行任务；执行后任务进入加工中，并切换主按钮为暂停。
- 暂停只能作用于加工中任务；暂停后主按钮恢复为执行。
- 停止只能作用于暂停、就绪、已停止或完成类状态，不直接停止运行中任务；停止后必须重新初始化。
- 删除只能作用于未执行中的任务。
- 新版任务树可删除未执行任务中的单个 WP 工件实例；删除必须二次确认，至少保留一个工件实例。确认后从任务 `workpieces` 移除该实例，并以剩余实例数同步更新任务加工数量与总体进度。
- 禁用是工序任务的前端软状态，不删除任务数据。新建工单弹窗禁用的工序同时写入执行禁用和左栏隐藏状态：任务定义保留，执行器仍跳过该工序，生产任务列表、筛选选项和工序计数均不展示该工序。装配体 / 生产任务条目只作为展开容器，不承载禁用状态。
- 新建工单第一步可对工序任务预览中的任意工序进行任务级软禁用；单条 toggle 和 checkbox 批量禁用 / 启用都写入同一份禁用状态。禁用工序不可触发弹窗内模型回显，但仍可被 checkbox 勾选用于批量解除禁用。创建后的任务保留这些工序定义，生产任务列表通过隐藏状态排除它们，执行器必须跳过禁用工序。
- 新建工单的「加工设置」提供贴板侧面打磨快捷禁用 / 启用；贴板侧面打磨固定由 `generated-grind-02`、`generated-grind-03`、`generated-grind-04` 标识，不通过列表序号或通用「打磨」名称推断。普通打磨和表面打磨不参与该快捷切换。
- 当前 `0162-01-010101` 演示工序序列的第 03 道为零件 `0162-01-010101-01` 的上料任务，在主筋板装配工位1回显；第 08 道为 `0162-01-010101-02 + 0162-01-010101-01` 装配体的上料任务，在主筋板装配工位2回显。两道上料都包含抓取和放置任务，不能根据“上料”名称复用同一对象。
- 清除列表是生产执行任务栏的展示队列操作，需经用户二次确认后按当前筛选后可见工单移出生产执行列表，不改变工艺规划的工序定义或模型数据。
- 任务状态监控中，任务节点状态由其工件实例聚合为未加工、加工中、已完成或异常。

## New Work Order Creation Rules

- 新建工单弹窗最左侧固定为工单栏；用户可新建并纵向 stack 多张待下发草稿工单，每张草稿自动生成 `WO-日期-序号` 工单号并自动选中。弹窗关闭后缓存草稿继续保留。
- 每张草稿工单独立保存装配体、工序勾选 / 禁用、加工数量、配盘结果和局部配置步骤；切换工单卡片不得丢失该卡片内容。
- 删除缓存中的草稿工单必须先通过就地 popover 二次确认；确认后只删除目标草稿及其勾选状态，不影响其它缓存草稿和已下发工单。
- 任务配置阶段在工单栏右侧显示项目管理结构树；右侧工作区上部预览模型，下部预览工序并提供单项 / 批量软禁用。
- 「下一步：预览配盘」位于局部 footer，只推进当前选中工单；进入配盘后工单栏和右侧整体骨架保持显示，仅将上部 3D 视窗替换为托盘依据视图，并将原工序预览位置替换为托盘卡片。
- 加工数量始终位于当前工件摘要下方的「加工设置」；配盘阶段不显示独立托盘结构树，托盘区位图展示位置关系，托盘卡片展示本次配盘所含零件物料。
- 「确认工单」位于「返回任务设置」右侧，用于确认当前草稿配置；配置完成后该工单卡片的 Checkbox 才可用。未设置数量、托盘溢出或尚未确认配置的卡片 Checkbox 必须禁用。
- 工单栏标题行的全选 Checkbox 只操作当前缓存中配置完成且可下发的工单；部分选中时显示半选，取消全选时只清除这些可下发工单的勾选状态。
- 弹窗 footer 左侧在有勾选项时显示已选工单数量，右侧「下发生产」只处理左栏 Checkbox 勾选的配置完成工单；未勾选草稿继续留在缓存区，已下发工单从缓存区移除并按勾选工单的左栏顺序追加到生产任务列表。
- 切换装配体时重置当前草稿的工序勾选和禁用；进入配盘预览时清除列表勾选和模型高亮，但保留禁用工序用于最终创建。

## Workpiece Monitoring Rules

- 工件实例状态包括未开始、进行中、已完成、异常。
- 工件实例必须展示当前工序、当前进度和视觉信息入口。
- 当前工序应来自任务创建时勾选的工序列表。
- 当前聚合工序的 `currentStepIndex` 只属于工件实例，用于右侧面板回显工步；工序完成或切换到下一道工序时重置为 0。
- 视觉信息入口应能跳转或切换到视觉监控视图，并保留当前工件上下文的演示语义。
- 生产工作台右侧面板当前只显示单步调试，宽度沿用原任务状态监控栏 360px；面板固定提供当前可见六个工位的选择器，选中工位通过 `productionWorkbenchProcessPlacements` 显式解析当前工序，无映射时显示工位空闲；任务状态监控组件保留代码实现但不在主页面挂载。
- 工艺规划与生产执行的主导航切换只改变工作区可见性，不卸载生产执行状态；该状态只要求在当前页面会话内保留，网址刷新后可重新使用 demo 初始状态。
- 右侧单步调试面板不显示独立的六工位选择器；当前工位通过生产工作台现有工位卡片点击选择，右侧详情面板回显当前工位和任务信息。工位卡片本体沿用原有布局和视觉形态。
- 右侧单步面板即使选中工位没有活动工序，也必须根据工位对应的演示工序显示完整聚合工步模板（复合工位显示完整合并工步列表）；空闲态标题只显示「工位工步」，不显示当前工步、任务或工件状态。单步模式下每个模板工步都可选中，选中后可触发对应单步演示。
- 单步调试面板顶部固定提供自动、单步、手动三种执行模式。自动模式按工位执行单元推进：同一物理工位或复合工位内，先按聚合工步顺序完成当前工位的全部工步，再进入任务序列中下一个工位；不能把整张工单的 process 列表作为自动模式的唯一推进边界。单步模式提供初始化和执行工步，点击执行后工步进入 `running`，同一按钮切换为可点击的暂停按钮；暂停只把当前任务 / 工件或空闲工位演示状态停在当前工步，不自动推进。执行期间允许切换查看三种模式，但只有当前执行模式、当前执行工位保留可操作的暂停按钮，其他模式的执行 / 初始化按钮和其他工位的执行按钮置灰。主生产任务为 `running` 时，工位详情中的手动设备控制全部禁用，并提示“请先停止生产任务”。真实任务按选中工步推进共享的 WP 状态，空闲工位进入本地演示执行状态；复合工位的单步执行允许在任务加工中打断自动顺序，把当前 WP 跳转到选中工步（可跨工序段落）后进入相同的执行 / 暂停闭环，进度不回退；手动模式只操作现场设备 Demo 状态、托盘载荷和 AGV 调度，不提供手动推进 WP 的统一执行块；复合工位手动模式用 tab 在两个物理工位间切换设备控制，设备状态按物理工位隔离。模式切换不复制或重置任务状态。
- 「二次定位/导入工件位置」结果属于正常工步结果，不属于视觉异常。结果身份必须包含任务、WP、执行单元段落和工步；同一身份重新执行或重新导入覆盖旧结果，切换任务、WP 或工位时不得串用。单步执行结果完成后停留等待下一次人工操作，自动执行结果完成后允许继续推进；两种模式都保留已完成工步的「查看工件位置」入口。
- 导入工件位置 Demo 第一次操作返回失败且不完成工步、不跳转视图；第二次操作返回成功结果。失败原因在当前定位方式弹窗的导入栏内回显。
- 右侧工位详情的选中对象是显式联合状态：生产工位或托盘工位。工位卡片和托盘卡片只写入该选择状态，不复制任务、托盘或 AGV 数据。
- 设备手动控制状态是前端 Demo 回显，与生产任务推进状态分离；启动、暂停、报警复位、回 HOME 位、打磨头开关和 J 轴点动不得直接改写当前 WP 工步。
- 设备命令从控制按钮触发到 Demo 命令回调完成期间使用按钮闪烁作为执行中反馈，命令完成后停止闪烁并更新设备回显；点动命令以按住到松开为完整执行周期。
- J 轴位置只通过点动按钮改变，位置框是只读回显；所有支撑、压紧和三轴分组必须复用同一点动行组件，不按工位重复实现。

## Vision Point Cloud Rules

- 当前视觉监控点云来源为 `Downloads/01120859-点云/oriPccInWrd.txt`，不得用随机点或合成几何替代真实扫描分布。
- 浏览器展示资源按固定步长 8 对原始 1,140,082 个 XYZ 点下采样，得到 142,511 个 Float32 世界坐标点；下采样只用于渲染性能，不改变点坐标。
- 默认视觉监控显示“当前无视觉内容”，不请求或渲染点云资源；视觉选择栏始终显示并按选项宽度居中；只有当前生产任务的 `WP-01` 第 06 道装配处于异常状态且带有 `abnormalProcessId` 时，才加载异常点云。
- `WP-01` 第 06 道装配异常时，页面不自动切换到视觉监控视图，而是通过全局异常 Alert 在右上角提示用户；用户可以点击 Alert 中的“查看详情”切换到视觉监控并打开右栏异常处理，也可以自行进入视觉监控并切换到当前异常对应的红色相机，选中该相机后打开右栏异常处理。
- 解除 `WP-06` 异常或切换到不含该异常的生产任务后，点云必须卸载并恢复待机状态。
- 八路视觉入口共享同一份点云数据，以八个预设观察角度表达桁架 1/2、搬运机器人 1/2 和焊接机器人 1/2/3/4；切换视角不修改生产任务状态。每路视觉使用显式状态：正常在线为绿灯、在线但存在告警或结果质量不足为黄灯、离线或未连接为灰灯；当前异常上下文通过 `abnormalVisionFeedId` 标识异常来源并覆盖为红灯；异常发生时，8 个 Tab 均可进入对应 Demo 异常面板，但一次只展示当前 Tab 的点云和结果面板。
- WP-01 第 06 道装配异常时，Demo 默认选中 `weld-1` / 焊接机器人1视觉；用户可通过视觉监控底部 Tab 切换 8 个异常面板。桁架面板展示 XYZ / Rx / Ry / Rz 和工件代号；从异常上下文切换到 `gantry-1` / `gantry-2` 时，右侧当前任务临时切换为 WP-01 第 04 项抓取任务，工件代号固定为 `0162-01-010101-02`，返回其它视觉后恢复当前第 06 道异常任务。搬运面板在装配异常态只展示直线 / 圆弧装配定位字段，模式控件与装配定位标题同排；直线模式下第一组、第二组装配基准各自包含基准距离和角度，圆弧模式下各自包含中心距，右侧不保留基准线回显框；双击左侧第 04 项抓取时临时切换为抓取六轴和工件代号 Hack。焊接面板展示测量交点 XYZ。所有面板均支持修改结果、重新扫描、跳过和确定；跳过或确定后解除当前视觉异常并保持任务暂停。
- 新版生产任务树支持 Demo 快捷入口：双击 `WP-01` 第 06 道「装配」时调用与自动 / 单步推进相同的异常状态构造，设置工件异常、任务暂停并进入视觉监控；该入口不新增独立状态机。
- Component Lab 保留 `VisionAbnormalCalibrationPanel` 原始样式、Demo 变体和 `GantryVisionScanPanel` 重构样式，并新增 8 视觉 Tab Demo。
- 点云视图为只读监控能力，允许旋转和缩放，不提供点编辑、删除或工艺规划操作。
- 视觉异常处理上下文包含当前异常工序标题、最近一次视觉结果、粗定位结果六轴坐标、异常原因、最近一次成功扫描使用的拍照位置基准和当前拍照位置草稿。异常原因块上方回显 `当前任务：WP 序号 · 工序名称工件对象`，例如 `当前任务：WP-01 · 装配0162-01-010101-02 + 0162-01-010101`，不得用任务工件名称替代工序标题；Demo 异常原因统一回显「点云识别失败」。
- 拍照位置支持绝对位置与相对位置两种输入模式。绝对位置直接编辑六轴拍照坐标；相对位置编辑相对最近一次成功扫描基准的六轴增量。模式切换只转换输入表达，两种模式必须映射到同一份最终绝对拍照位置。
- 用户修改拍照位置后，最近一次视觉结果立即标记为待重新扫描；重新扫描使用当前最终绝对拍照位置，成功返回后替换视觉结果并把本次扫描位置更新为新的重置基准。扫描失败时保留旧结果和用户输入。
- 重置只撤销最近一次成功扫描之后的输入修改，不触发重新扫描；绝对位置恢复为扫描基准，相对位置恢复为六轴零增量。
- 坐标无效、正在扫描或当前视觉结果与拍照位置不一致时不可确认。确认接受最新视觉结果和对应拍照位置；跳过放弃本次视觉结果和未确认修改。两种操作都解除当前视觉异常并保持生产任务暂停，等待用户手动恢复执行。
- 异常上下文消失后，右栏异常处理关闭并清空本次临时输入、扫描状态和结果反馈；同一异常上下文中处理尚未打开或已关闭时，可从全局异常 Alert 的“查看详情”或重新切换红色异常相机打开，打开入口不改变任务异常状态。
- 正常定位结果可驱动视觉监控加载同一真实点云，但不设置 `abnormalProcessId`、不触发全局异常 Alert，也不复用跳过 / 重新扫描 / 确定状态机。右栏标题固定为「视觉结果」，六轴结果只读；导入来源隐藏底部视觉选择栏。

## Workbench Station Card Rules

- 工位卡片方案只影响生产工作台的展示方式，不改变任务状态机、工序推进、工位映射或异常处理逻辑。
- 水平方案和 skew 方案使用同一份工位展示字段：工位名称、四态标签和加工零件。
- 工位对外标签统一为四态：无当前工序映射或内部状态为 `idle/default` 时显示“空闲”；内部状态为 `running` 时显示“执行中”；内部状态为 `paused` 时显示“已暂停”；内部状态为 `abnormal` 时显示“异常”。异常处理完成后工件进入 `paused`，工位标签随之切换为“已暂停”。
- 工位卡片和右侧单步调试工位按钮必须消费同一个 `getProductionStationDisplayStatus` / `getProductionStationStatusLabel` 映射，名称、标签文字和标签颜色不能各自重新推导。
- “加工零件”读取当前工序 `partObject`，不读取生产任务 `name`。单零件工序展示对应零件号，组合工序展示由 `+` 连接的多个零件号。
- “执行中”使用绿色语义，“已暂停”使用琥珀色语义，“异常”使用红色语义；异常工位不展示“查看视觉”入口。

## Production Model View Rules

- 顶部悬浮 tab 可在生产监控、模型视图和视觉监控之间切换；视觉监控和模型视图只替换中间视窗内容，不移除左右栏。
- 旧样式任务树中点选工序任务后，应自动进入模型视图，并保留左侧生产任务栏和右侧单步调试栏；新样式任务树的任务选择与模型高亮解耦。
- 模型视图结构树展示当前工件的零件层级，作为中间模型视窗内部左侧悬浮面板呈现，沿用工艺规划样式 C 的紧凑缩进和零件显示规则；零件支持单选，选择只改变生产执行模型视图的本地回显状态，不写入工艺规划数据。
- 模型视图的结构树下方展示只读属性参数浮层，当前装配体的 4 个零件均以纵向可折叠卡片展示，零件标题只使用编号；字段固定为名称、材质、重量、厚度，并与工艺规划的零件属性语义一致。树节点单选时自动展开对应卡片，工序关联和树节点选中分别复用结构树的关联 / 选中 fill 语义。收起属性参数时整个浮层收缩为标题条。属性仅用于现场识别，不可在生产执行中编辑或写回工艺规划。
- 工序任务的零件对象来自工艺规划生成的 `partObject`，生产执行只解析零件对象，不在此处展示焊缝、打磨线或装配基准特征节点。
- 点选工序后的模型高亮复用工艺规划隔离语义：关联零件保持 100% 显示，非关联零件在结构树和模型视窗中半透明显示。
- 结构树零件选中只覆盖模型视图本地回显，不改变旧样式的工序选择或新样式的任务选择。结构树零件选中时，该零件作为唯一关联对象复用相同隔离高亮；再次点击该零件或点击视窗空白处清除选择，并恢复已有的旧样式工序高亮。

## Tray And AGV Rules

- 上料任务可由理料区计划托盘卡片按当前生产任务创建或复用，包含该卡片的组件代号、数量、图外取货点 `00` 和卡片托盘号卸货点。
- 空托任务在上料位置托盘物料用完后生成，取货点可由系统计算，卸货点可人工录入。
- 满托任务在下料位置托盘满料后生成，包含组件代号、数量、取货点和卸货点。
- AGV 任务执行中需要明确反馈，直到手动或系统确认完成。
- AGV 任务只有在 `已完成` 后才能归档；归档任务进入历史任务列表，不再参与当前调度、点位占用和计划任务匹配。历史任务恢复后保留原任务字段与 `已完成` 状态。
- AGV 任务点击执行前必须校验现场点位占用互斥：任一执行中任务的取货点和卸货点都视为托盘整体视图临时锁定点位；新任务的取货点或卸货点只要与这些点位重合，就不能进入执行中，并需要提示用户无法执行。
- AGV 任务进入执行中后，取货点保留其实际料框与载荷状态，可视卸货点显示“已预约”；确认到达时释放来源并把料框与载荷写入卸货点。下方计划卡片不受执行中任务影响。
- 理料区计划只绑定新建工单缓存池中“配置完成”且尚未“下发生产”的工单；理料区顶部用横向短名称 tag 切换这些工单。工单下发后立即从缓存池、tag 和计划摆盘区移除，不能再通过理料区查看该工单的计划；没有缓存工单时不回退到当前生产任务。
- 托盘位置编号为 1-9；托盘信息至少包含位置、区域、托盘类型、组件代号、数量和占用状态。
- 托盘卡片不改用工位三态标签，继续消费现场物流状态：`空闲`、`已预约`、`空托`、`已配盘`、`已占用`、`取货中`、`执行中` 等。托盘标签表达托盘 / AGV 现场状态，不代表工位工序状态。
- 生产工作台轴测托盘卡片展示托盘标号、现场状态和载荷摘要；已占用卡片必须显示零件或成品名称及数量，空托卡片显示“空料框”，已预约卡片显示等待 AGV 入站。01 为上料区，09 为下料区；02-08 统一作为装配托盘位，不再区分装配阶段，卡片和地面均不显示其区域归属。
- 01-09 生产工作台托盘卡片都可作为右侧工位详情入口。01-08 在手动模式中可编辑托盘物料和数量、控制搬运机器人并按选定取货点创建手动 AGV 上料任务；当前托盘号是该任务的卸货点。09 只提供状态与物料详情。
- 托盘卡片字段固定为：首行托盘号和状态 tag；中行载荷或任务名称；底行左侧为等待 AGV，右侧为数量。上料预约中行显示待入站零件号、底行显示“等待AGV”；零件/成品到达中行显示名称、底行右侧显示“数量 N件”；空托回收中 tag 显示“空托”、中行显示“空托回收任务”、底行左侧显示“等待AGV”；成品下料中 tag 显示“已预约”、中行显示完整 WP 工件号（当前 demo 为 `WP-0162-01-010101`）、底行同时显示“等待AGV”和“数量 N件”。空闲状态折叠中行和底行。
- 生产工作台中处于 `loaded` 或 `full` 的占用托盘在编号右侧提供编辑入口，并通过弹窗修改；零件类型只能从当前工件的 01-04 四个零件对象中选择，数量必须为正整数。保存同时更新 `traySlots` 的物料与数量，并同步未完成的同托盘运输任务；取消或关闭不改变现场数据。普通展示态和托盘管理计划卡片保持原样。
- 托盘 Demo 自动推进存在编辑保护：用户进入编辑态时，待执行的托盘推进不应抢先覆盖编辑内容；保存或取消后从一个完整 Demo 步进间隔重新计时。
- 托盘配盘按物料种类成堆展示，数量表示该堆同零件物料件数。新建任务 mock 固定展示 4 种料；加工数量 1-2 时四种料集中在 01 号托盘，数量 3 时 01-03 号托盘承载四种料，末位托盘可合并显示剩余料种，数量 4-5 时 01-04 号托盘各承载一堆同零件物料。01 号零件优先放入 01 号托盘，其余零件按托盘序号顺移。数量大于 5 时，同一种料按每堆最多 5 件拆成连续批次且不与其他料混放，依次使用 01-08；09 是下料区，不参与新建任务配盘。满 5 件的托盘显示“满盘”警告。当前 8 个可用托盘的上限为加工数量 10；数量达到 10 时显示已到上限且不能通过 stepper 增加，超过该上限的手工输入显示托盘不足并禁止确认任务。
- 托盘计划视图使用真实零件 STL 的俯视图识别物料种类；同一托盘存在多种零件时，当前 demo 在连续托盘承载面内按单列展示各物料堆，不绘制内部料框或分割线。该单列顺序只表达托盘物料构成，不代表经过托盘真实尺寸、间距、旋转角度、工装或禁放区校核后的现场坐标。

## UI Boundary Rules

- 生产执行页面不应修改工艺规划的模型树、特征提取、工艺参数和任务序列生成逻辑。
- 生产执行 3D 产线视图表达生产现场状态，不承载工艺规划中的模型点选、特征提取或路径点位编辑工具；生产模型视图仅复用工序到零件的隔离回显，不允许编辑工艺规划数据。
- `0162-01-010101` 的 `ProductionTaskTreePanel1` 作为旧样式留档，必须保留工艺规划生成的 24 个工序名称和零件对象。
- `ProductionTaskTreePanel2` 在每个完整 WP 分组内展示 16 条现场执行聚合任务。装配任务吸收装配、翻面压紧和合并焊接语义；新版另外保留明确的上料、抓取、翻面和下料节点。
- `ProductionTaskTreePanel2` 与样式 C 工艺规划必须消费同一份固定 16 工序定义；第 03 道上料对象固定为主筋板零件 `01`，第 08 道上料对象固定为 `02 + 01` 装配体。生产执行展示工序层，不把工艺规划内部任务平铺为额外工序行。
- 合并焊接只改变上层任务语义；生产执行右侧单步调试不再逐条展开定位扫描执行和定位焊接执行，装配段的压紧、定位扫描、定位焊接等设备级动作在工位工步展示中合并为单步「贴板【编号】焊接」，复合工位2 的 04 装配段末尾保留「主筋板组件下料抓取 / 放置」。
- `ProductionTaskTreePanel2` 将原任务概要升级为工单概要：左侧显示折叠 caret 和新建工单时自动生成的工单号，右侧显示工单状态或理料状态下拉；概要不显示排单序号、装配体图号或件数；展开时显示总体进度并直接挂载原 WP 列表。
- 工单层级不得修改 WP 容器和内部工序任务条目的结构、尺寸、间距、颜色、状态灯、禁用态、批量选择与展开行为，也不得通过新增内层卡片或缩进压缩原有可用宽度。
- 新版任务条目保持单行「序号（批量选择时 Checkbox）、状态灯、工序名称、零件对象」结构，不在条目中显示工位、托盘或行尾禁用入口；序号默认恒显，hover 不切换为 Checkbox。
- 每条新版任务必须通过显式映射关联生产监控视图的工位或托盘，不得从工序名称、零件尾号或列表序号推断。工位映射可以驱动工位卡片；托盘卡片只由托盘、料框和 AGV 的现场状态驱动，不随左侧工序执行、暂停或异常直接变色。
- Demo fake data 必须能从生产执行、托盘调度或设备监控语义解释，不应硬编码无法追溯的业务状态。
