# 虚拟仿真 Product Spec

## Goal

虚拟仿真是工艺规划的下游验证模块。工艺规划发送场景承接样式 C 装配工序的独立副本；本地导入 Demo 在同一副本内展示第 06 道正面装配任务和第 12 道反面装配任务。每条装配任务使用自己的支撑机构 `J1-J8`、压紧机构 `J1-J6` 轴值和合并焊接任务扫描/焊接点位生成机器人后处理指令，并提供工位场景回显、外部轴限位样式、指令检查、播放验证和本地导出。

虚拟仿真只读发送或导入时的数据副本，不修改、不回写工艺规划。页面不提供独立“保存”，仿真结果以本地后处理指令文件导出。

## Reference Implementation

- 虚拟仿真的程序列表、任务层级、程序参数、点位数据字段及节点选择联动，以同事维护的 [`chenghe12581-ops/Pathsim`](https://github.com/chenghe12581-ops/Pathsim) 仓库为实现基准。
- 北煤机原型应复用 Pathsim 已有的信息层级和字段语义，不另行发明程序树、详情 Tab 或轴值展示位置；只允许为适配北煤机统一导航、设计 token、工艺规划数据副本和 React 组件边界做必要转换。
- 当本 Spec 与 Pathsim 当前实现存在未明确的细节差异时，优先核对 Pathsim 源码与其 `docs/虚拟仿真模块功能文档.md`，新增产品差异必须先补充到本 Spec。

## Users

- 工艺规划工程师
- 机器人调试工程师
- 产线调试和 Demo 演示人员

## Entry And Navigation

- 北煤机主导航固定包含 `工艺规划 / 虚拟仿真 / 生产执行 / 产能统计`，三个已实现工作区可以直接切换。
- `/虚拟仿真` 由 `BeimeiAssemblyLinePage` 统一承载，不创建第二套模块导航。
- 样式 C 第 06 道装配工序提供“发送仿真”入口；工序内的翻面压紧和合并焊接不再分别提供仿真入口。
- 每次从第 06 道装配发送都创建一份新的独立仿真副本，不查重、不覆盖。
- 已有仿真副本时，主导航“虚拟仿真” tab hover 显示 caret；无论当前是否正在虚拟仿真工作区，单击 tab 都先展开或收起下拉菜单，不直接跳转界面。选择菜单内的具体仿真副本后才切换到对应工作区；菜单底部固定显示“新建仿真任务”。主导航的一项代表一份工艺规划发送副本或一个本地文件副本，不代表副本内的单条装配任务。
- 仿真任务菜单的任务标题使用 `14px / 400`，副标题使用 `11px / 400`：标题显示副本名称；副标题统一为 `本地导入 · 文件名称` 或 `工艺规划 · 装配体名称`，不使用“工艺规划发送”等旧文案。工艺规划下拉中的项目任务标题与此保持一致。
- 没有仿真任务时不显示 caret，点击 tab 直接进入包含本地导入入口的空界面。
- 虚拟仿真工具栏复用工艺规划面包屑的 14px 字号、字重和灰/黑文字层级。只有当前仿真任务携带工艺规划任务路径索引时，才显示带左箭头的“返回工艺规划”文字入口；点击后恢复第 06 道装配工序上下文。本地导入任务显示 `本地文件 > 文件名`，但不显示返回入口；没有当前仿真任务时只显示 `虚拟仿真`，不显示 `0162`、分隔符或返回入口。面包屑不在 320px 区域继续追加工序和副本名称，避免截断。

## Data Source

- 每个仿真副本包含一条或多条装配任务。工艺规划发送副本包含被发送的一条装配任务；当前本地文件 Demo 固定包含第 06 道和第 12 道两条装配任务。
- 每条装配任务携带来自对应工序翻面压紧任务的 8 个支撑机构轴值 `J1-J8`，并使用本地 Demo 默认的 6 个压紧机构轴值 `J1-J6`；两组轴值均独立维护，不回写工艺规划。
- 工艺规划后续修改不影响已创建副本；需要新数值时重新发送并创建新副本。
- 主导航下拉中的每一项是一份仿真副本，翻面压紧和合并焊接只作为副本内当前装配任务的数据。
- 焊接路径以当前焊接任务选择的焊缝特征曲线为几何来源，并统一组织为 6 个焊缝段、12 个端点。每段必须保留清晰可见的起终点间距，不能再压缩为近似重合的点。扫描与同序号焊接点保持 X/Y 和姿态一致，并按扫描参数的正向 ΔZ 离开焊接点；当前 Demo 默认偏移 `80 mm`，因此扫描和焊接各保留 12 点。
- 焊缝段按整条曲线的弧长位置分散布置，端点跨度约为曲线长度的 `8%`；扫描点的 Z 向安全距离由扫描参数表达，不通过模型包围盒投影或规则网格伪造坐标。
- 工位模型使用项目内的 `public/beimeiji_weld_0623.urdf` 和 `public/urdf-stls/` 本地资源；URDF 中的滑台与双机械臂在同一工位场景中渲染。工件使用应用侧标定的落台位姿，直到 URDF 增加正式装夹基准帧。
- URDF 机械臂关节状态按装配任务独立维护，只用于场景姿态和位姿 mock 回显；不写入支撑/压紧机构轴值、程序指令或导出数据。
- “新建仿真任务”和页面“导入文件”复用同一本地文件选择流；当前 Demo 使用两秒居中灰色浮窗示意“本地选择文件”。
- 每次本地导入都新增一份本地文件副本，不替换当前副本，也不清除已有副本中的程序和参数。
- 当前 Demo 的每份本地文件副本包含与工艺规划第 06 道、第 12 道同结构的两条模拟装配任务；第 06 道显式映射正面工位，第 12 道显式映射反面工位。正式 `.rt` 协议稳定后再在 service/parser 层接入。
- 本地文件 Demo 的第 06 道装配任务固定包含 `焊接任务1 / 焊接任务2` 两组同结构 Mock 数据，每组各有独立的焊缝段 ID、机器人分配、支撑/压紧轴值和加工程序；第 12 道仍只包含一组“焊接任务”。焊接任务2的轴值在焊接任务1基础上使用确定性偏移，确保加工程序2的轴值与加工程序1可见不同。

## Page Layout

- 顶部工具栏：`320px / minmax(0, 1fr) / 420px`，复用工艺规划工具栏高度、颜色、字号和按钮规则。
- 左侧 `320px`：标题为“任务列表”，标题左侧不显示 icon；副本内的装配任务作为多个根节点，每个根节点下是一组或多组“焊接任务”，再向下展示各自的“焊缝段1-6”。当前装配任务使用浅橙底、品牌描边和品牌文字明确选中，只展开当前任务的焊接层级；未选任务收起内部层级。扫描和焊接不拆成两个任务节点，焊接任务与焊缝段条目保持 `28px` 紧凑行高，焊缝段行不显示“扫描 2 点 / 焊接 2 点”等数量文案。
- 装配任务根节点提供删除入口；删除前使用危险确认，确认后整条删除该装配任务及其内部焊接任务、焊缝段、已生成程序和任务级视图状态。删除当前任务后选择相邻任务；副本内最后一条任务删除后关闭该副本。
- 中间：React Three Fiber 视窗，加载任务关联零件模型和焊接点位。
- 右侧 `420px`：标题为“程序列表”，标题左侧不显示 icon；程序树、横向拖拽条和下半区详情共同置于外层留白中，左右和底部为 `p-ds-150`，顶部压缩为 `pt-ds-050`，让根程序更贴近标题下方；详情容器宽度约 `396px`，不贴左右栏边。下半区将 Tab 与程序参数或点位数据收纳于独立的带灰色 stroke 详情容器，明确表达其归属当前选中的加工程序。详情容器直接使用工艺规划同款灰底，Tab 与内容共用同一块灰色面，内容区保留 `p-1.5` 内间距；点位数据区不再叠加左右 `p-3`，点位卡片使用完整可用宽度约 `382px`，与工艺规划点位卡片一致。
- 程序树与下方详情区之间复用工艺规划任务栏的横向拖拽分隔条：`12px` 点击区内使用轻量细线，hover 与拖拽时显示浅橙色反馈。默认程序树高度为 `220px`；拖拽只调整右栏上下幅面，不改变页面三栏宽度，并限制程序树高度在 `72px - 260px`。
- Component Lab 的工艺执行场景应用区同步展示第 06 道双焊接任务、加工程序1 / 加工程序2和程序生成分页解锁交互；预览按实际 `320px / 420px` 左右栏尺寸检查分栏与平铺视图溢出。

## Station Rules

- 工位正反面使用固定工序的显式 `simulationSide`，不根据工序名称猜测。
- 主筋板装配工位1的焊接任务回显正面工位。
- 主筋板装配工位2的焊接任务回显背面工位。
- 兼容旧工序时，“筋板及贴板翻转工位”归背面。
- 视窗内只提供 `正面工位 / 背面工位` 页签，当前任务不适用的一侧禁用，不在页签内显示状态文字；hover 时以 tooltip 提示暂不可用。不再提供独立的 `数模查看` 页签。
- 切换左侧装配任务时，视窗立即切换到该任务的显式工位侧别，右侧程序列表切换到该任务独立维护的程序，播放和焊缝选择重置。

## 3D Viewport

- 场景页签放在视窗内部左上角，不占用模块级标题栏；正面 / 背面工位切换复用生产执行“生产监控 / 模型视图 / 视觉监控”的同款 Tab 壳和状态：`40px` 容器、深 Slate 活动项、白色非活动 hover 面。不可用工位置灰，状态仅在 hover tooltip 中显示。
- 工位场景将本地 URDF 工位、双机械臂和应用侧标定后的工件合并渲染。左上角常驻“调整装配体位置”浮窗，提供世界/父系坐标切换及 `X / Y / Z / RX / RY / RZ` 六个带单位输入；输入只变换工件、焊缝和点位，工位设施和地面网格保持原位。
- 当前 Demo 的父级是视窗根节点，因此世界坐标与父系坐标共享同一零点；坐标系切换保留当前副本的输入值，为后续接入装配层级变换保留语义。
- 视窗不展示操作方式说明，也不展示左下角的工位 / 单位灰底标签；仅保留右上角的重置视图图标。
- 当前装配任务尚未生成加工程序时隐藏“机器人位姿”浮窗；程序生成成功后才在视窗右上角显示。浮窗使用玻璃表面，`Robot1` 与 `Robot2` 两组信息上下 stack 同时显示，满足双机任务播放时的并行观察。每个机器人标题行提供独立 caret，默认展开，收起后保留机器人名称和坐标系 radio，只隐藏位姿与关节详情。每组都独立提供世界、父系、物体坐标系 radio，并只读回显对应机器人末端的 `X / Y / Z / RX / RY / RZ` 和 `J1-J7`；`J1-J6` 对应机械臂旋转关节，`J7` 对应该机器人的 URDF 滑台轴并以 `mm` 显示。位姿由当前 URDF 关节状态执行正向运动学得到。浮窗不修改支撑/压紧外部轴、程序指令或导出数据。
- 使用 `OrbitControls`：左键旋转、右键平移、滚轮缩放，并提供视图重置。
- 新建、切换或本地导入仿真任务后，视窗默认使用包含工作台、双机械臂和工件的工位全景。点击左侧“焊接任务”切换到工件正 Z 方向的顶视焊缝视角，同时回显 6 个相互分离的焊缝段；点击某个焊缝段时只缩小回显范围，不改变相机尺度。
- 正面/背面工位使用独立的工位全景相机：工位长边保持水平，平台、双机械臂和工件完整入镜；点击右侧任意程序节点都会重新触发该全景构图，重置视图恢复当前工位的标准角度。
- 点位标记复用工艺规划打磨路径的“点球 + 编号标签”共享组件：扫描使用蓝色 `S段号-点号`，焊接使用橙色 `W段号-点号`。扫描标记在对应焊接点的正 Z 上方，保证两套点位、标签和段线均可分辨。
- 切换到适用的正面或背面工位时，清除左侧焊接任务/焊缝段的选中态；工位场景不保留数模点位回显的任务选择。
- 扫描与焊接使用相同的段内 X/Y 范围，但扫描沿正 Z 保持安全距离；程序数据保留各自独立的 12 个点位和工艺参数；3D 视窗不把 12 点连接成一条连续长路径。
- 工位设施在本地 URDF 加载后即与工件一起渲染；工件按应用侧标定值落台，避免仅依赖工件包围盒推导装夹位置。
- 播放器在视窗底部居中悬浮，不挤压视窗布局。
- 播放器始终显示；没有任务时播放、暂停、重置和倍速控件全部禁用。

## Processing Program

右侧使用 Pathsim 原型的加工程序层级；每个焊接任务生成一组同序号加工程序：

```text
加工程序1
├─ Robot1程序
│  ├─ 扫描程序1 / 焊接程序1
│  ├─ 扫描程序2 / 焊接程序2
│  └─ 扫描程序3 / 焊接程序3
└─ Robot2程序
   ├─ 扫描程序4 / 焊接程序4
   ├─ 扫描程序5 / 焊接程序5
   └─ 扫描程序6 / 焊接程序6
```

- 点击“程序生成”先打开焊缝段机器人分配弹窗，逐段选择 `Robot1 / Robot2`；默认焊缝段 1-3 分配给 Robot1，焊缝段 4-6 分配给 Robot2。
- 多焊接任务时，弹窗一次只展示当前焊接任务的焊缝段分配；标题显示“焊接任务1 / 焊接任务2”，行尾显示页码和左右 caret。首次打开停留在第 1 页，“程序生成”置灰；用户翻到最后一页后解锁，之后返回任意已访问页面仍保持可点击。单焊接任务不显示翻页器，程序生成按钮直接可用。
- 一个焊缝段的扫描和焊接必须绑定同一执行机器人，不允许分别分配。程序树中仍保留扫描程序和焊接程序，是因为工具、速度和工艺命令不同，不代表任务列表重新拆分。
- 程序树只展示程序对象，不把 PTP / LIN 指令作为可展开树节点；点位在下方“点位数据”中查看。
- 程序树的根程序与扫描/焊接子程序使用 `12px` 主信息；Robot1/Robot2 分支使用 `11px` 常规字重与 `text-ds-text-control-muted` 作为次要分类标题。扫描/焊接子程序默认使用 `text-ds-text-control`，仅当前选中项提升为品牌橙色。扫描/焊接图标左缘与所属 Robot 名称左缘对齐，且不显示尾部点数。
- 选中加工程序或 Robot 父级时，当前节点的全部子程序仅使用品牌文字色表达关联选中，不使用 fill 或 stroke；直接选中节点继续使用主选中态。
- 选中右侧程序对象时，左侧任务列表同步标记该程序范围包含的焊缝段：扫描/焊接子程序关联单个焊缝段，Robot 父级关联其下全部焊缝段，根程序关联当前任务全部焊缝段；左侧直接选中焊接任务或焊缝段时，以直接选中态优先。
- 焊接顶视状态下，当前程序树节点保持详情内容，但使用与工艺规划“仅显示详情”一致的品牌描边态，不使用浅橙底；选择任一程序节点后，视窗清除左侧焊接选择并恢复当前任务适用工位的全景。选择左侧焊接任务或焊缝段则重新进入顶视焊缝视角。
- 选中“加工程序1 / 加工程序2”时，下方只显示“程序参数”Tab，并分别展示对应焊接任务独立维护的支撑机构 `J1-J8` 与压紧机构 `J1-J6` 轴值；不显示执行方式、参与机器人或启动方式参数，也不在左侧任务列表展示轴值。
- 两组机构轴值必须与工艺规划、Component Lab 共用 `ProcessJointAngleRow`：每行使用 `40px / 7fr / 5fr` 的 label、slider、stepper 数字输入三列结构，列间距 `12px`，行间距 `8px`，行内上下 padding `6px`，slider 与数字输入高度均为 `32px`。每组的 `J1` 范围为 `0–200 mm`，其余轴为 `-180–180°`，slider 与输入框双向同步。
- 加工程序详情与支撑/压紧轴值、Robot 子程序和扫描/焊接程序共同保持清晰的数据归属，不允许不同加工程序之间互相覆盖轴值或指令。
- 生成第 06 道本地任务时，右侧依次创建加工程序1和加工程序2；两棵根程序均包含 Robot1 / Robot2 双机分支。加工程序2读取焊接任务2的确定性偏移轴值，例如支撑机构 J1 与压紧机构 J1 均应区别于加工程序1。
- 选中 `Robot1程序 / Robot2程序` 时，下方只显示“程序参数”Tab，回显机器人编号和对应一组 URDF 姿态 mock，不展示另一台机器人的姿态调节。
- 选中扫描程序或焊接程序时，下方显示“程序参数 / 点位数据”两个 Tab。
- 扫描/焊接程序的程序参数字段复用 Pathsim 语义：程序名称与“定位焊扫描程序 / 定位焊焊接程序”类别、机器人编号和指令点位；不显示对应焊缝名称、坐标系或工具。点位数据保持现有 Pathsim 同名点位卡片样式，只调整指令数据，回显运动方式、目标位姿、外部轴 `E1` 与速度 `S`。点位卡片标题和 `PTP / LIN` 标识使用 `11px / 400`，参数标签固定预留两个字符宽度，确保后续输入框统一对齐；字段视觉继续复用工艺规划紧凑参数样式：`ds-label-input-compact` 的 `8px` label-control gap、`32px` 只读字段、两列 `12px` gap，以及工艺规划共享的轻量下划线 Tab。
- 扫描/焊接程序的点位卡片可直接选中；同一时间只保留一个当前点位，卡片选中态与当前执行机器人关联。当前 Demo 暂在右侧机器人位姿浮窗的对应 Robot 名称后显示“当前点位”Tag，不增加独立信息行或 Robot 容器 fill/stroke；后续接入轨迹或逆解时沿用该点位选择状态驱动机器人到位。

指令至少回显：

- `move_type`: `PTP` / `LIN`
- 每个扫描/焊接子程序固定生成 6 个点位：`P_APPROACH_1`、`P_SCAN_START / P_WELD_START`、`P_1`、`P_2`、`P_SCAN_END / P_WELD_END`、`P_DEPART_1`
- `speed`（字段名 `S`）：`PTP` 速度以 `%` 显示，`LIN` 速度以 `mm/s` 显示
- `process_command`: `SCAN_START`、`SCAN_END`、`WELD_START`、`WELD_END`
- `target_pose`：`P_APPROACH_1` 使用 `J1 / J2 / J3 / J4 / J5 / J6 / E1`；其他路径点使用 `X / Y / Z / RX / RY / RZ / E1`，与工艺规划姿态字段保持一致
- `P_APPROACH_1` 的默认关节值直接采用 Pathsim 示例：`15 / -60 / 10 / 180 / 30 / 0`；Robot1 的 `E1=-1200 mm`，Robot2 的 `E1=+1200 mm`

第一阶段的程序生成器把当前任务的扫描与焊接点位适配为上述指令结构，用于确认产品流程和界面，不代表最终机器人品牌后处理算法。

## Export

- 每个装配任务按内部焊接任务分别维护加工程序1、加工程序2等独立加工程序。
- 生成结果保存焊缝段级 `robotAssignments`，导出文件携带该分配关系，重新生成时以当前分配作为草稿初值。
- 页面不设置独立“保存”；点击“程序生成”后可直接使用当前仿真副本导出后处理指令演示文件。
- 当前仿真任务已有加工程序时，再次点击程序生成弹窗内的“程序生成”必须先显示“确认替换程序”二次确认；确认后替换现有程序列表和指令数据，取消则返回分配设置且不修改已有程序。支撑机构与压紧机构轴值均沿用当前设置。
- 切换主导航或仿真副本时虚拟仿真工作区保持挂载，已生成程序不丢失。

## Playback Rules

- 没有加工程序或没有指令时不能播放。
- 只允许在任务适用的正面或背面工位全景播放；左侧焊接任务或焊缝段处于选中状态时不播放。
- 程序树的当前选中节点就是播放范围，选中节点本身不自动播放：
  - 选中 `加工程序1 / 加工程序2` 时，播放该加工程序下 Robot1 与 Robot2 的完整双机程序；两台机器人同步启动、并行执行。
  - 选中 `Robot1程序 / Robot2程序` 时，只播放所选机器人的完整程序，不启动另一台机器人。
  - 选中扫描程序或焊接程序时，只播放该机器人下所选的一段程序。
- `Robot1程序 / Robot2程序` 在树中上下排列只表达同一双机程序下的两个并行分支，不表达先后顺序。根节点使用“双机并行”标识，程序参数回显“参与机器人 / 启动方式”，双机播放说明使用两条并行程序泳道和同一同步起点。
- 播放器保持播放、暂停、重置、进度和倍速结构，不在播放器上方附加额外信息条。原“仿真进度”文字位置改为 `当前范围：所选程序 · 执行方式`，并与下方进度条保持更明显的纵向间距。主播放/暂停按钮恢复品牌重点色并放大为左侧三个核心按钮中最大，播放中显示暂停图标，暂停后显示继续播放图标；其左右分别提供“快退 3 秒 / 快进 3 秒”按钮，按钮外壳不填充、图标内的三角形实色填充，按钮不进入橙色选中态，每次点击只执行一次跳转，不再保留独立的暂停按钮。重置仅在暂停状态可用，其余状态置灰。
- 切换程序树节点时暂停当前播放并将该范围进度重置为 0%；不同范围不继承上一范围的播放进度。
- 当前尚未接入真实机器人轨迹、逆运动学或控制器。点击播放后运行与进度绑定的确定性 URDF 姿态 mock：扫描使用较小幅度的快速关节摆动，焊接使用较慢且幅度略大的摆动；选中的 Robot 或根程序按子程序范围驱动对应一台或两台机械臂，暂停和跳播保持姿态同步，完成时回到手动基准姿态。该 mock 只驱动视窗网格与位姿浮窗，不改写右侧 URDF 关节输入、外部轴 J 值、程序指令或导出数据；不弹 Modal，也不把 mock 进度当作真实运动结果。
- 切换任务后播放状态和进度重置。
- 播放完成后再次播放，从 0% 重新开始。

## Non-goals

- 不实现真实机器人品牌后处理器。
- 不实现碰撞检测、机构联动、真实机器人运动学或真实外部轴限位计算；当前只演示发生条件与样式。
- 不请求未来后端 API。
- 不修改 MES 页面或 MES 导航。
