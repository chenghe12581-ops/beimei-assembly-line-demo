# 托盘管理组件说明

## 组件边界

- 组件文件：`src/app/components/production/TrayManagement.tsx`。
- 组件定位：生产执行域的 Feature Component，负责托盘配盘预览、托盘管理完整页面、理料区视图、AGV 调度列表和托盘位置图展示。
- 页面职责：`ProductionExecutionPage.tsx` 只保留 `traySlots`、`trayTasks`、当前生产任务和日志更新等 demo state，并通过回调传给托盘页面组件。
- 对外导出：`TrayManagementPage`、`TrayReferenceStrip`、`TrayMapPreview`、`TrayAllocationCard`、`buildTrayPlanAllocations`，以及 `TraySlot`、`TrayTask` 等托盘相关类型。

## 交互方式

- 「托盘管理」作为生产执行视窗内的独立悬浮入口进入完整页面，不加入「生产监控 / 模型视图 / 视觉监控」tab 分组。
- 页面 Header 的返回按钮回到生产执行，不清空 AGV 任务、托盘位置或当前生产任务选择。
- 页面 Header 的「理料区视图」入口切换到独立理料区屏幕；理料区屏幕可返回托盘管理。
- 理料区视图使用独立路径 `/生产执行/理料区视图`，直接访问该路径时默认进入理料区屏幕并隐藏生产执行主导航；返回托盘管理或生产执行后恢复主导航。
- 「新建任务」按钮在 AGV 任务调度表内新增一条任务行，不跳转到生产任务弹窗，不离开托盘管理页面。
- 托盘管理 AGV 调度标题栏不提供「生成上料任务」；上料执行入口放在理料区计划托盘卡片的序号行。
- AGV 调度表表头固定为「任务类型 / 执行零件 / 取货点 / 卸货点 / 状态 / 操作」。
- 表内「任务类型」「执行零件」「取货点」「卸货点」通过下拉栏修改，修改后直接更新当前任务行；「状态」只读回显为居中 badge，不提供下拉修改；AGV 任务表不显示数量字段。
- 「执行零件」在上料和满托任务中承载运输载荷；空托任务不填写零件。
- 「取货点」「卸货点」支持可视托盘 01-09 与图外来料/回收位 `00`、出库位 `10`。00 和 10 只出现在任务路线中，不画入当前托盘区位图。
- AGV 调度行支持「执行」「确认到达」「归档」「删除」四个文字按钮动作；只有已完成任务可归档。执行中行使用橙色左侧高亮和状态脉冲。执行后可视卸货点显示已预约，确认到达时来源释放且载荷落入可视卸货点；已完成行保留 badge。
- AGV 调度标题栏在「新建任务」左侧提供「历史任务」入口并回显归档数量。历史任务仍在托盘管理页面内展示，表格字段只读且只提供「恢复」动作；恢复后任务以原完成状态回到当前任务列表。
- 「新建任务」使用品牌主题色主按钮；「历史任务」保持中性次级文字入口。
- 点击执行发生点位冲突时，不做整行错误态；只将当前行中重复的取货点/卸货点下拉框标红，用户点击其他 AGV 任务行或修改点位后清除标红。
- 托盘管理页面和理料区视图都使用同一份「托盘整体视图」现场回显：上层区位图表达持续的现场托盘状态与执行中任务的目的地预约；托盘管理页面只显示上层区位图，理料区视图在其下追加当前任务的配盘计划和零件明细，不提供计划 / 实际切换 tab。
- 托盘依据视图中的上层区位图和下层托盘明细都按现场平面方向从左到右排列为 `09 / 08 / 07 / 06 / 05 / 04 / 03 / 02 / 01`，不要按数字升序显示。
- 两个页面都不显示右侧「托盘信息」悬浮面板；上层使用真实区位底图表达区域、位置和占用摘要，不另行显示物流方向文字；理料区视图下层九个托盘明细表达零件种类、俯视图和数量。
- 新建工单弹窗中，每张草稿工单在自己的第二局部阶段复用托盘管理同款 `TrayReferenceStrip`，用于在弹窗级「下发生产」前展示配盘结果；上层区位图只保留托盘编号、占用框和满盘提示，不显示上料区 / 下料区等灰色区域文字，下层托盘明细保持与托盘管理计划视图一致。
- 理料区视图顶部使用横向滚动的工单 tag 卡片切换工单，不使用下拉选择器；标签只来自新建工单缓存池中“配置完成”且尚未“下发生产”的工单。标签主行显示缓存池同源的自动工单号，副行显示工件名称，避免同一工件的多张缓存工单显示为无法区分的重复名称。点击「下发生产」后，工单从标签和计划摆盘区移除；没有可查看工单时显示空状态，不回退显示当前生产任务的计划。
- 理料区视图的上层整体区位图显示位置、现场状态和实际占用的零件名称；执行中 AGV 的可视卸货点显示「已预约」，到达后按实际托盘状态显示「已占用」或「空托在位」。实际「已占用」点位可点击释放为「空托在位」，用于演示人工取料后的回收准备；计划零件、数量和满盘信息统一由下方计划摆盘卡片表达。新建生产任务预览仍不在托盘矩形内显示“已配盘”或料种状态，只有达到 5 件的托盘显示“满盘”tag，未占用位置以虚线弱化显示。
- 计划视图的每个已配盘托盘使用 `public/part-topviews/` 中由真实 STL 生成的透明俯视图；单料居中放大，多料在连续托盘承载面内纵向单列排列，显示零件号和 `×数量`，托盘内部不绘制料框、网格或分割线。
- 多料单列是当前 demo 的信息可视化变体，不代表零件已经按托盘真实尺寸、间距或工装禁放区完成摆放校核。
- 理料区视图底部卡片始终按配盘计划显示零件明细；取货点/卸货点关系和实时占用只在上方整体区位图中表达，避免把 AGV 状态混入计划物料卡片。
- 理料区每张可见计划托盘卡片的序号行显示「执行」和「确认到达」。首次执行按该卡片的托盘号、零件明细和数量创建或复用 `00 -> 托盘号` 上料任务；执行中禁用执行并启用确认到达，完成后两个按钮均禁用。任一执行中 AGV 与计划任务共享 `00` 或目标托盘位时，其它冲突卡片的执行按钮禁用。

## 配盘规则

- 配盘以“一种料放一堆”为原则，数量表示每堆同零件物料的件数。加工数量大于 5 时，同一种料按每堆最多 5 件拆成连续批次，拆出的批次不与其他料混放。
- 新建任务配盘可用顺序固定为 `01 / 02 / 03 / 04 / 05 / 06 / 07 / 08`；01 号零件优先放入 01 托盘，其余零件按托盘序号顺移，09 始终是下料区，不能参与新建任务配盘。
- 每批达到 5 件时，托盘卡片右上角和区位图状态显示琥珀色“满盘”警告。当前 8 个可用托盘对应加工数量上限 10；数量达到 10 时，输入框下方显示已到上限，增加 stepper 禁用。所需批次数超过 8 时，数量输入下方显示托盘不足 warning，并禁用确认。
- 新建任务 mock 固定展示 4 种料。
- 加工数量 1-2 时，02 号托盘集中展示四种料。
- 加工数量 3 时，02-04 号托盘承载四种料，末位托盘可合并显示剩余料种。
- 加工数量 4-5 时，01-04 号托盘分别放置一种料；加工数量大于 5 时，依次为每种料的 5 件满盘和余数盘。例如加工数量 6 使用 01-08 共 8 个托盘。
- 当前为前端 demo 规则，不直接连接真实 AGV、PLC 或仓储接口。

## 样式规定

- 托盘管理使用生产执行工作区的完整页面样式：白底 Header、浅灰页面底色、无遮罩；Header 提供返回生产执行和进入理料区视图的入口。
- 托盘管理页面占满生产执行工作区可用高度，AGV 调度表作为主要工作区并在表格主体内部滚动；理料区视图单独占满页面内容区。
- 页面 Header 保留标题和明确的页面导航动作，理料区视图 Header 提供返回托盘管理入口。
- 托盘管理页面采用 AGV 调度工作区并在下方保留现场托盘整体视图；理料区屏幕复用同一整体视图并追加横向计划摆盘依据带。
- 历史任务模式隐藏下方托盘整体视图，AGV 历史任务区使用 `flex-1` 填满页面 Header 以下的全部可用高度，表格主体继续独立滚动。
- AGV 调度区使用表格结构，表头与数据列对齐；每条任务只占一行，不额外展示任务 ID、模式或状态 badge 辅助行。
- AGV 调度区域和下方托盘整体视图在完整页面中均使用 `flex-1` 填充内容区，AGV 区域保留 `300px` 最小高度、整体视图保留 `248px` 最小高度；新增大量任务时只在表格主体内部使用鼠标滚轮滚动，表头固定并在表格内容滚动时使用 `shadow-ds-sticky-overlap` 下投影遮挡态。
- AGV 调度标题栏使用 `48px` 高、`px-5` 水平内边距；理料区视图标题说明使用页面 Header 和内容区标题，不再与 AGV 表格争用弹窗高度。
- 理料区卡片动作使用紧凑文字按钮，并与满盘状态一起放在序号行右侧；执行使用品牌橙文字，确认到达使用绿色文字，禁用态统一使用浅灰色。
- 表格行保持紧凑可扫描：下拉控件统一复用 `ProcessSingleSelect` 的 `sm` 尺寸和 `ds-dropdown-surface` 浮层样式，AGV 表格内下拉需使用 portal 模式避免被滚动区域裁切；表格列间距使用 16px 以避免选框贴得过近，删除确认 popover 使用磨砂玻璃 `ds-popover-glass-surface` 和 `ds-popover-glass-arrow`，操作按钮高度 28px、使用文字按钮样式且按钮组内部保持 4px 紧凑间距，长文本在单元格内截断。
- 托盘管理页的整体视图使用弹性高度填充下方内容区，区位图随整体视图区域展开；理料区视图区 header 和主体均使用白底。上层区位图和下层托盘卡片放在同一个最小宽度为 `1600px` 的容器内，窄视窗时同步横向滚动；区位图负责位置关系与实际 AGV 状态，下层卡片固定表达计划摆放的零件与数量。理料区屏幕模式下区位图高度为 `280px`，上方工单 tag 与托盘卡片区域共享剩余纵向空间；新建生产任务预览仍使用普通紧凑模式。
- 主交互和执行中状态文字使用品牌橙；已配盘状态文字使用绿色；空闲和备用状态使用 slate / zinc 中性色；不要使用默认蓝色作为控件主题色。
- 托盘地图必须基于 `北煤机托盘区位.svg` 生成的图例专用底图，底图移除原始 01-09 路径文字和装配区域 stroke，由 HTML 层叠加清晰编号、上料区 / 下料区名称与现场占用状态；整体视图 SVG 所在布局容器使用中性灰底，并在 SVG 与 HTML 编号 / 占用标记之间增加低透明度灰色层，使布局图整体明度低于下方托盘卡片但不影响标记辨识；底图保持可辨识灰阶，不得淡化到无法识别现场结构。
- 上层区位图保留的上料区 / 下料区标签距区域顶边约 20px，水平位置必须由对应托盘矩形的最左边和最右边计算总横宽中点，不按区域框左边写固定偏移；02-08 不显示装配区标签。托盘矩形内编号 tag 使用 11px 字号和更充足的 padding，09 号 HTML 占用框需针对清理后的 SVG 位置向左校准。
- 区域标签和所属托盘编号的颜色规则为：上料区 / 01 使用 teal，02-08 统一使用 zinc 中性色，下料区 / 09 使用 rose；02-08 不通过颜色、文案或 tag 区分装配阶段。已使用项保持清晰，未使用项使用低饱和浅色层级。
- 已占用托盘的位置色同时用于整体区位图矩形、新建任务预览矩形和下方托盘卡片的边框 / 浅色底 / 轻阴影。整体区位图只显示现场状态，计划明细不进入区位矩形。
- 区位图与托盘明细之间保持 12px 间距；下方托盘明细只显示当前视图实际使用的托盘卡片，按现场方向保持 `09 / 08 / 07 / 06 / 05 / 04 / 03 / 02 / 01` 顺序，未使用卡片隐藏；卡片区域始终使用四列等宽和两条固定网格行，卡片之间保持 16px 间距，四张卡片在最小 1440px 行宽下约为 348px，卡片宽度不随当前可见数量变化；不足五张时第二行保持为空。托盘管理的「计划上料摆盘」分组中，两条网格行各固定为约 `128px` 高，保证卡片头部和一行零件条目完整可见；分组内容可独立纵向滚动，上方区位图保持固定。新建工单弹窗的托盘卡片使用自然高度包裹物料条目，加工数量为 1 且四种料集中在 01 号托盘时，卡片必须完整包住全部零件条目，不让条目溢出边框。托盘布局图例固定不随滚动移动；托盘管理和新建生产任务配盘预览复用同一套 `TrayReferenceStrip` / `TrayAllocationCard`。
- 托盘卡片内的单料和多料共用紧凑单列条目：托盘管理和配盘预览中的 compact 卡片填满当前图例容器高度；新建工单弹窗的非 compact 预览卡片使用内容自然高度，不固定为等高拉伸；卡片外壳左右内距为 16px，卡片顶部到序号 / 状态行保留 10px，上方内容区域到第一条零件保留 10px；卡片 header 显示托盘序号、满盘 `5/5` 等状态，理料区变体再显示「执行 / 确认到达」，不显示装配区域文案，并固定为满盘 tag 和动作按钮所需高度，使不同状态的卡片物料内容起点对齐；每条约 44px 高，俯视图统一为约 `72 × 44px`，图片区域使用浅灰色底，图例与右侧两行文字保持 14px 间距，零件内容区左右内距为 6px，条目随内容区同步扩展；条目内部左右各保留 8px padding；零件名称和第二行辅助信息均使用 12px 字号，通过字重区分主次；卡片顶部序号 / 状态行左右各保留 2px padding，零件条目上下 stack gap 固定为 16px，divider 放在间距中线位置，与上下条目内容各保持约 8px 距离。compact 卡片不截断零件条目，仅在条目总高度超过卡片内部可用高度时显示条目区滚动；独立组件示例仍保留 288px 最小高度变体。鼠标 hover 或键盘 focus 零件俯视图时，通过 portal 显示低不透明度磨砂玻璃大图 popover，预览面不使用不透明白底，避免被托盘卡片和弹窗滚动区域裁切。
- 生产执行现场托盘卡片的中间载荷 / 任务行使用 `16px` 字号；底部等待 / 数量行与中间行之间使用 `8px` 间距，两种卡片方案共用该行级规范。非空卡片的可见高度使用 flex `h-fit` 包裹内容和等量上下 `py-2` padding，不用 `h-full` 拉伸底部留白。
- 生产执行现场托盘卡片支持 `material` 单料和 `materials` 多料两种输入；多料时第一项显示为中间主载荷行，后续零件名在其下方逐行排列，卡片高度继续由 flex `h-fit` 自动包裹全部内容。
- 生产执行工作台中已占用托盘卡片在编号右侧提供铅笔编辑图标，点击后通过统一玻璃弹窗编辑 01-04 零件类型和数量；零件类型使用组件库 `ProcessSingleSelect`，下拉项和已选值均显示完整零件名称，不只显示末两位编号。普通卡片保持原尺寸与布局，托盘管理计划卡片继续只读。弹窗提供关闭、取消和保存操作。
- 生产工作台 01-09 托盘卡片整卡作为托盘工位详情入口，但不新增持久选中描边；铅笔编辑按钮必须停止冒泡，不能在打开弹窗时重复触发详情切换。01-08 的空托也可从右侧手动详情打开同一物料编辑弹窗。
- 空闲托盘卡片同样使用 `h-fit` 和对称 `py-2` padding，空闲态不再使用固定 `h-9`，保证卡片上下留白一致。
- 文案字号以 10-12px 为主，物料名称必须 truncate；托盘管理页面和理料区视图中的长名称通过常显浮层补充，新建任务预览中可继续通过 hover 浮层补充，不撑开托盘卡片。
- 托盘清单卡片复用 `TrayAllocationCard`；空位、折叠位、单料、多料状态必须在 Component Lab 的「托盘清单卡片」分区展示。
- 托盘整体视图中的 01-09 号托盘不得折叠；独立清单场景可以保留空托盘折叠态作为组件变体。
- 俯视图与区位底图分别由 `scripts/generate_tray_part_topviews.py`、`scripts/generate_tray_zone_legend_svg.py` 生成；需要调整时修改生成脚本并运行 `npm run generate:tray-assets`，不要手工修改生成资源。
- 组件样式变化需优先在 `TrayManagement.tsx` 内收敛，不把托盘管理页面或理料区屏幕样式散落回生产执行页面组件。
